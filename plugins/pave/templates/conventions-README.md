# Conventions

Rules that apply to every repo, whatever the language.

Loaded for every task. Language-specific rules go in `<language>.md` and
service-specific rules in `<service>.md`, which wins on conflict.

Keep this file about how code is written. Workflow rules - gates, contracts,
escalation - belong in the hub `CLAUDE.md`, and a standing instruction you
want every agent to carry belongs in `config.yaml` under `rules`.

These files describe how the code already is. A rule in `config.yaml` is what
you are telling the agents to do, so a rule wins where the two disagree.

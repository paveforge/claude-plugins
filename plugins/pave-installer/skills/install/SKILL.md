# Pave Installer — install pave-setup

Install the `pave-setup` skill for the named coding-agent host. The skill tells
that host where the Pave source is and how to build Pave for itself; this
command converts nothing and never creates or changes a Pave hub. It installs
for the current user only.

Accept exactly `codex` or `kiro`. For anything else, including a scope such
as `project`, stop and show those choices. Do not guess a host.

First show the complete plan. The marketplace package uses the repository root
as its plugin root; `--plugin-dir` development uses this plugin's directory, so
resolve both:

```bash
installer="${CLAUDE_PLUGIN_ROOT}/plugins/pave-installer/scripts/pave-host.py"
[ -f "$installer" ] || installer="${CLAUDE_PLUGIN_ROOT}/scripts/pave-host.py"
python3 "$installer" plan-install <host>
```

Pass its output on. A `conflict` means an existing file was not written by
Pave Installer, or was edited after it was installed; it is preserved. A line
marked `(Pave Installer 0.1)` is a file generated by the old Codex adapter:
`remove` deletes it, `preserve` keeps it because the user edited it. Then run
the installation without asking another question — invoking this skill is the
user's instruction to install:

```bash
python3 "$installer" install <host>
```

Exit 2 means `pave-setup` was installed where it could be, but one or more
edited files were preserved. Name those paths. Any other non-zero exit is a
failure; pass the error on and do not claim installation succeeded.

On success, tell the user to open the host and run `pave-setup` there:
`$pave-setup` in Codex, `/pave-setup` in Kiro. It builds Pave for that host,
and should be run again after every update. A new host session may be needed
before the skill appears.
